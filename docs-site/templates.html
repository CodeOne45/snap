Templates

A template is a plain directory: a snap.toml manifest plus the captured files, with {{placeholders}} in both file content and paths. Templates live under ~/.config/snap/templates/ and are fully hand-editable.

Manifest

[template]
name = "api-starter"
version = "1.0.0"
description = "A minimal HTTP API service"

[[variables]]
name = "name"
prompt = "Service name"
type = "string"
validate = "^[a-z][a-z0-9-]*$"

[[variables]]
name = "port"
type = "int"
default = 8080

[[optional]]
name = "docker"
prompt = "Include a Dockerfile?"
default = true
paths = ["Dockerfile", "docker-compose.yml"]

[[hooks.post]]
run = "git init"

Variables

Each declared variable has a type (string or int), an optional validate regex (string only), and an optional default. A variable with no default and no explicit --var is either prompted for (interactively) or an immediate error (--yes, or via MCP).

Placeholder filters

A placeholder can apply a filter: {{name|pascal}}, {{name|title}}. Filters only change how a value is rendered at each use site — the underlying resolved value is unaffected.

Optional blocks

Toggle one with --with docker / --without docker (CLI, repeatable) or the toggles map (MCP). An unset block falls back to its declared default. Every block's resolved state — not just the ones explicitly set — is recorded in .snap/origin.toml's [toggles] table.

Post-generate hooks

A [[hooks.post]] block is a shell command that runs once the target directory is fully written. Hooks never run silently: the CLI asks for confirmation (remembered per template@version after the first approval); MCP's create_project needs allow_hooks: true on every call.

Versioning

[template].version must be strict MAJOR.MINOR.PATCH semver — snap capture always starts a template at 0.1.0. The local store keeps every version a template has ever had (one directory per version), so an old base stays available even after the template moves on.

snap template bump client-site patch   # 1.0.0 -> 1.0.1
snap template bump client-site minor   # 1.0.1 -> 1.1.0
snap template bump client-site major   # 1.1.0 -> 2.0.0

snap new/snap show resolve a bare name to its latest version, or pin an exact one with name@version (mirroring remote templates' @tag/@commit syntax):

snap new client-site@1.0.0 ~/code/site --var name=site

Testing a template

An optional [test] block lets a template author sanity-check it before anyone else generates from it:

[test]
check = "go build ./... && go test ./..."

[test.vars]
name = "sample-project"
port = "8080"
snap test client-site

snap test generates into a throwaway temp directory using [test.vars], runs check there (the same mechanism as a post-generate hook), and exits with the check's result — usable as a CI step. A template with no [test] block can't be tested this way.
