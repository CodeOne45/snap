CLI reference

Commands

CommandWhat it does
snap capture <source-dir> --as <name>Scan a project and save it as a template
snap new <template> <target-dir>Generate a project from a template
snap listList available templates
snap show <template>A template's variables, optional blocks, and raw file tree
snap template bump <name> <major|minor|patch>Create a new version of a template by bumping its latest version
snap update <target-dir>Three-way merge a generated project up to its template's latest version
snap test <template>Generate a template's declared sample and run its check command
snap status <dir>...Report which template/version each project came from, and which are behind
snap mcpRun as a Model Context Protocol server over stdio
snap (no arguments)Launch the interactive TUI wizard

Flags that work across commands

FlagEffect
--dry-runPrint the plan without writing anything
--jsonPrint the plan/result as JSON instead of writing or printing human-readable text
--yes / -yNever prompt: a missing required value is an immediate error
--force(new only) remove an existing non-empty target directory first
--var key=value(new) set a template variable, repeatable
--with name / --without name(new) toggle an [[optional]] block, repeatable
--help, --versionStandard Cobra flags, on every command

Exit codes

CodeMeaning
0Success
1User error (bad input, missing variable, etc.)
2Internal error

Remote templates

<template> also accepts a git-hosted reference in place of a local template name:

snap new gh:acme/web-starter ~/code/site --var name=site
snap new gh:acme/web-starter@v1.2.0 ~/code/site         # pinned to a tag
snap new https://example.com/templates/api.git@abc1234 ~/code/api

Unpinned, it resolves the remote's current default branch on every run; pinned, it's reproducible fully offline once fetched once, from a local cache under ~/.config/snap/cache/.

Full JSON shapes and the .snap/origin.toml format are documented in docs/cli-json-contract.md.
