MCP server

snap mcp runs over stdio and exposes the same core use cases as the CLI to an agent: same safety guarantees (path-escape rejection, non-empty-target refusal), same JSON shapes as --json.

Connecting an agent

Add to your MCP client's config (e.g. .mcp.json):

{
  "mcpServers": {
    "snap": {
      "command": "snap",
      "args": ["mcp"]
    }
  }
}

Tools

ToolWhat it doesSide effects
list_templatesList templates, optionally filtered by a substring of name/descriptionNone
describe_templateA template's variables and raw file treeNone
plan_projectResolve variables + toggles and build the write plan. template may be a remote reference. Response includes a stats field (file/byte/approx-token counts)None locally; may fetch/cache a remote template's commit
create_projectGenerate a project. allow_hooks: true required to run any hooks. Response includes statsWrites files; runs hooks only if allowed; appends a usage-log entry
capture_templateScan a project, propose scored placeholder candidatesNone
save_templateRe-scan and save only the accepted candidates as a templateWrites files

Resources & prompts

Resources: template://<name>/snap.toml and template://<name>/README.md. Prompt: new-project (describe → ask for missing variables → plan → confirm → create).

What's different from the CLI

  • create_project/save_template never prompt — a missing required variable is an immediate error.
  • Both refuse to write into an existing non-empty directory; there's no agent-facing --force.
  • Hook approval isn't remembered between calls — every create_project call states its own allow_hooks intent.

An agent, end to end

A typical flow: list_templates → describe_template → plan_project (preview) → create_project (write). This is exactly the sequence this repo's own Gate 2 test exercises against a real, shipped example template, with no manual fixes to the output afterward.

Recipes over MCP

Recipes (snap add) don't have MCP tools yet — today an agent applies one via the CLI. Equivalent tools (plan_recipe, apply_recipe, list_recipes) are planned next, matching plan_project/create_project's shape.
